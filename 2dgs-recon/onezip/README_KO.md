# microtom_recon one-zip v0.2.2 — 사진 → 2DGS 3차원 복원

화분 하나를 A3 ChArUco 보드 위에 놓고 찍은 사진 폴더를 넣으면, Kaggle 또는 Colab 에서 셀 실행 한 번으로 개체 전체의 서펠(2DGS) 복원이 나옵니다.
**검증된 결과가 아닙니다.** 마스크는 자동이고, 길이(mm)는 보드 기준이며 독립 실측으로 검증되지 않았습니다.

## 1. 찍는 법
- `board/charuco_a3_10x7_38mm.pdf` 를 A3 에 **100 % 크기**로 인쇄합니다(칸 한 변 38 mm 를 자로 확인). 평평한 판에 붙입니다.
- 화분을 보드 가운데에 놓습니다. 촬영 중 화분과 보드의 위치 관계가 바뀌면 안 됩니다(카메라가 돌거나, 보드째 돌립니다).
- 카메라 비율은 **1:1(정사각형)**, 한 개체는 같은 카메라·같은 해상도로 찍습니다. HEIC, JPG 모두 됩니다.
- 한 바퀴를 다 돌며 **40–80장**: 낮은 높이(45° 아래), 중간, 높은 높이(58° 위) 세 줄 + 바로 위 몇 장.
- 사진마다 보드가 절반 이상 보이고, 식물 전체가 들어오고, 초점이 맞아야 합니다. 밝고 고른 빛, 보드에 반사가 없게 합니다.

## 2. 실행 (3단계)
**Kaggle**
1. 이 zip 을 비공개 Dataset 으로, 사진 폴더를 또 하나의 비공개 Dataset 으로 올립니다.
2. 새 Notebook 에 `RUN_KAGGLE.ipynb` 를 불러오고(File → Import Notebook), 두 Dataset 을 Input 에 추가합니다.
   Settings: Accelerator **GPU T4 x2**, Internet **On**.
3. Run All. 결과는 `/kaggle/working/recon_out/` 에 생깁니다.

**Colab**
1. 런타임 유형을 **T4 GPU** 로 바꿉니다.
2. 왼쪽 파일 창에서 `/content` 에 이 zip 과 사진 zip(예: `photos.zip`)을 올립니다.
3. `RUN_COLAB.ipynb` 를 열어 모두 실행합니다. 결과는 `/content/recon_out/` 에 생깁니다.

**직접 실행**
```
python run_recon.py --photos <사진 폴더> --out <결과 폴더> [--plant-id 이름] [--mask auto|auto+stem|sam2|color] [--iters N] [--holdout 2] [--skip-train] [--skeleton skeleton_v1.json --tprox-inputs <폴더>]
```
중간에 끊기면 같은 명령을 다시 실행하세요. 끝난 단계는 건너뜁니다. 처음부터 다시 하려면 결과 폴더를 지웁니다.

## 4. 멈추는 경우 (한국어 안내가 나옵니다)
GPU 없음(또는 Kaggle P100) · 쓸 수 있는 사진 20장 미만 · 방위 범위 270° 미만 · 보드를 못 찾은 사진 30 % 초과 · 정사각형이 아닌 사진.

## 5. 한계
- **마스크: `mask_method_new_ungraded`.** `--mask auto` 는 색(초록) 기준 마스크 + 형상 껍질 + SAM 2.1 tiny(실행 중 내려받음)로 가는 줄기를 더하는
  방식이고, 사람 마스크로 채점된 적이 없습니다. 초록이 아닌 부분(익은 열매, 꽃, 노란 잎, 아주 밝은 잎)은 빠집니다.
  `--mask color` 는 색 기준만 쓰는 예비 방법(`fallback_low_quality`)입니다. `--mask unet` 은 v0.2 에 가중치가 없어 쓸 수 없습니다.
- **보류 시점 IoU 는 `auto_mask_reference_not_human`**: 같은 자동 마스크와 비교한 값이라 마스크의 잘못은 드러나지 않습니다.
- 규모는 보드에서만 옵니다. 인쇄 배율이 다르면 길이가 그만큼 틀립니다. 개체 높이는 서펠의 z 범위이며 화분 윗면 기준이 아닙니다.
- 학습 설정은 우리 R3-1b 구성(1512 px, 7,000회, gsplat 1.5.3)과 같지만 마스크가 달라 결과는 R3-1b 와 같지 않습니다.
- 인터넷이 필요합니다(패키지 설치, SAM 가중치). T4 에서 사진 60여 장 기준 대략 1시간 안팎입니다.

## 6. v0.2.2 에 없는 것
- **줄기 모델, `--skeleton auto`**: 학습된 줄기 검출기가 없습니다. `auto` 는 한 줄로 거절합니다.
- 그룹·축 분류를 노트북 안에서 만드는 일(아래 7절).
- 형질(엽면적 등), MTG, 광 모델, 인터랙티브 뷰어, 메쉬.
- 카메라 두 대로 찍은 촬영, ChArUco 보드 없이 찍은 촬영, 여러 개체 일괄 처리.

## 7. 복엽 라벨 (7단계, T-Prox) — 왕복이 한 번 필요합니다
7단계는 복원된 서펠에 "어느 복엽인가"를 붙입니다. 두 가지를 직접 주어야 하고, 둘 다 없으면 1–6단계만 끝내고 안내 한 줄을 냅니다.

| 필요한 것 | 누가 만드나 | 어떻게 주나 |
|---|---|---|
| `skeleton_v1.json` (복엽마다 선 하나, 보드 좌표 m) | 사람 (클릭 페이지) | `--skeleton <파일>` |
| 그룹·축 분류 (`groups.npz`, `geometry.npz`, `geometry.json`, `axis_labels.npz`, `TPROX_INPUTS_META.json`, 그리고 그 복원의 `surfels_full.ply`) | 프로젝트 PC 의 파이프라인이 **이 실행의 `surfels_full.ply` 로** 만듦 | `--tprox-inputs <폴더>` (Kaggle: 비공개 Dataset 으로 Input 에 추가) |

순서: ① 1–6단계 실행 → ② 결과 폴더를 내려받아 PC 로 전달 → ③ PC 에서 그룹·축 분류를 만들어 Dataset 으로 올림 → ④ 그 Dataset 과 스켈레톤을 붙여 다시 실행.
④ 에서는 Dataset 에 든 복원을 그대로 쓰고 1–6단계를 다시 돌리지 않습니다(그룹은 그 복원의 서펠 번호에만 맞습니다). sha256 이 다르면 7단계는 멈춥니다.

- 계산은 고정된 코드 그대로입니다: `pc_absorb.py`(가중치 묶음 A, 기하만) 뒤에 엽축 단계. 가중치 파일은 없고 GPU 도 쓰지 않습니다. 몇 분에서 십여 분 걸립니다.
- 나오는 것: `labels_tprox.npz`, `tprox_meta.json`, `points_tprox.ply`(서펠마다 `leaf`, `stem` 속성), `REPORT_TPROX_KO.md`.
- **라벨의 뜻**: `tprox_unverified_until_heldout` — 보고되는 것은 **배정 비율**이지 정확도가 아닙니다. 정확도는 우리 파일럿 개체 하나에서만 측정됐습니다(다른 마스크로 0.750).
  `skeleton_human` — 선은 사람이 준 것. `groups_sam_candidates_only` — 그룹을 SAM 후보 한 층으로만 만든 경우.
  `stem_from_axis_classifier_unscored` — `stem` 은 붙여 준 축 분류에서 줄기처럼 분류된 서펠일 뿐이고 정확도를 잰 적이 없습니다.
- 스켈레톤이 다른 좌표계(화분 윗면 기준, mm 단위)이거나 다른 복원에서 만든 것이면 7단계만 멈추고 1–6단계 결과는 그대로 둡니다.
- **스켈레톤은 그 복원 위에서 만든 것이어야 합니다.** 다른 복원에서 찍은 선은 표면에서 벗어날 수 있고, 7단계는 선을 옮기거나 붙이지 않습니다.
- **한 복엽을 선 여러 개로 그렸다면** 스켈레톤에 같은 잎 번호가 적힌 선은 한 잎으로 묶입니다(v0.2.1). v0.2 는 선마다 다른 잎으로 읽었습니다.
  원래 PC 복원에서는 이 차이만으로 파일럿의 사람 라벨 일치가 0.750 에서 0.451 로 떨어졌습니다. 이 zip 의 파일럿 복원에서는 묶어도 0.525 → 0.531 로 거의 같았고,
  남은 차이는 복원 쪽에서 옵니다(겹쳐 있는 잎 4·5 가 한 겹처럼 복원되어 잎 5 가 잎 4 로 배정됨). 같은 채점 방식의 한계값은 0.758 입니다. `checked_on_pilot_only`.
- 고정 코드는 파일럿 개체에 맞춰 쓰여 있어, 잎 배치에 따라 스스로 멈출 수 있습니다. 그 경우 7단계만 멈추고 안내가 나옵니다.
- 주축만 있는 스켈레톤으로는 복엽 라벨이 나오지 않습니다(복엽 선이 있어야 합니다).
- 시험한 것: Kaggle 에서 파일럿 개체 1개. 시험하지 않은 것: Colab, 다른 개체, 사람이 클릭 페이지에서 새로 만든 스켈레톤.

## 8. 마스크 옵션 두 가지 (v0.2.2)
| `--mask` | 내용 | 더 필요한 것 | 라벨 |
|---|---|---|---|
| `auto` (기본) | 색 기준 + 형상 껍질 + SAM 2.1 tiny(기본 가중치) 줄기 단계 1회 | 없음 | `mask_method_new_ungraded` |
| `auto+stem` | 위 마스크로 한 번 학습한 뒤, 우리 R3-1b 복원의 마스크 단계를 더하고 다시 학습: 줄기 단계 재실행(M2), 흙 분류(M3), 앞 시점 마스크를 렌더 깊이로 옮기기(M1), 렌더에 있는데 마스크에 없는 곳 보충(M5) | `--weights <폴더>`, `--pot-top-mm`, `--pot-side-mm` | `mask_auto_plus_stem_r31b_steps` |

- `--weights`: 우리가 미세조정한 SAM 가중치 `sam2.1_hiera_tiny_leaflet_v5_4plants.pt`(156 MB)가 든 폴더. **zip 에 없습니다.** 비공개 Dataset 으로 붙이세요. 없거나 해시가 다르면 한 줄로 멈추고, `auto` 로 바꿔 실행하지 않으며, 다른 곳에서 내려받지 않습니다.
- **화분 값 두 개는 `auto+stem` 에서만 필요합니다. `--mask auto`(기본)는 이 값 없이 그대로 실행됩니다.** 기본값은 없고, 빠지면 실행 전에 멈춥니다.
  - `--pot-top-mm`: **보드 면(화분이 놓인 인쇄면)에서 흙 표면까지의 높이**(mm). 자를 보드에 수직으로 세워 화분 테두리까지 재고, 테두리에서 흙 면까지 내려간 깊이를 뺍니다. 받침 위에 놓였으면 받침 높이도 포함됩니다.
  - `--pot-side-mm`: **화분 윗면 안쪽의 한 변 길이**(mm). 둥근 화분이면 안쪽 지름을 넣습니다. 이 크기의 정사각형 안에서만 흙과 식물을 가릅니다.
  - 예(우리 파일럿 화분): `--mask auto+stem --weights <폴더> --pot-top-mm 66 --pot-side-mm 62`. 값이 몇 mm 틀리면 흙이 마스크에 들어오거나 줄기 밑동이 빠질 수 있으니 `masks_sheet.jpg` 를 꼭 보세요(청록 = 더해진 곳, 빨강 = 빠진 곳).
- 학습을 두 번 하고 초기 점도 두 번 만들므로 GPU 시간이 대략 두 배입니다. 첫 번째(`auto`) 결과는 `base_auto/` 에 남습니다.
- 보류 시점의 마스크는 `auto` 그대로입니다(보류 시점 IoU 는 여전히 `auto_mask_reference_not_human`).
- R3-1b 에 있던 단안 깊이 초기 점은 넣지 않았습니다. R3-1b 에서 줄기가 나아진 것이 마스크 때문인지 깊이 초기화 때문인지는 갈라 본 적이 없습니다.
- 시험한 것: 우리 파일럿 개체 1개(`checked_on_pilot_only`). 결과는 프로젝트 보고서에 있습니다. 다른 개체·다른 화분은 시험하지 않았습니다.
